## 4. 架构合理性检查

### 4.1 结论

| 检查项 | 结论 | 说明 |
|---|---|---|
| 技术栈 | ✅ 合理且前后一致 | Java 17 + Spring Boot 3 + Spring MVC + Validation；Vue 3 + TypeScript + Vite + Pinia + Element Plus + ECharts |
| 架构形态 | ✅ 合理 | 模块化单体 + 双前端 + 单库单缓存 + MinIO；当前团队与数据规模无需微服务 |
| 模块边界 | ✅ 基本清晰 | `auth`、`student`、`subject`、`course`、`question`、`interviewbank`、`route`、`study`、`interview`、`stats`、`system`、`security`、`ai` 职责可追溯 |
| 跨模块调用 | ✅ 有约束 | 02 明确“只经对方 Service 接口与 DTO，不跨模块直接访问 Mapper/实体” |
| 双端认证 | ✅ 合理 | 学员端/管理端独立账号、独立 JWT 域、独立登录态；管理端 RBAC 权限点 |
| 临时态方案 | ✅ 合理 | 不建任务表；导入预览、文档解析任务、面试逐题评分暂存 Redis；符合当前规模 |
| 实时传输 | ✅ 收口正确 | SSE 仅用于 AI 面试逐题评分；简答批改走 P-P02 同步响应 |
| AI 降级 | ✅ 已修正 | 简答批改降级关键词判分；面试评分不模拟打分，AI 不可用返回 20010；语音识别按需求降级提示 |
| 消息队列 | ✅ 不引入 | 当前无必须异步化的长任务；面试文档解析为唯一异步场景，用 Redis 任务态即可 |

### 4.2 架构层面需关注的风险

1. **P-P02 同步 AI 批改的请求时长**：简答题 AI 批改同步返回，若模型超时，练习提交会被阻塞。建议在 `ai` 层设置明确超时（例如 10s）并降级关键词判分，响应标记 `degraded`；该点已在 P-P02 规则中体现，实施时需落实。
2. **P-P01 的 `practiceId` 未落库**（2026-11-11 决议）：`practiceId` 由服务端生成 UUID，P-P02 仅校验格式与限流，不存 Redis 会话；答案由服务端按 `questionId` 重判分，伪造 `practiceId` 不会产生错误得分。残余风险是客户端可提交非本次组卷的题目并计入统计，当前接受（练习为自主学习场景，前端进度本地控制）；如后续需要严格防构造，再升级为签名令牌或 Redis 组卷。
3. **操作日志异步落库**：02 采用同进程线程池异步写 `operation_log`，进程异常退出时可能丢日志。若审计要求强一致，需改为事务内同步写或增加补偿；当前需求对审计实时性要求不高，可接受。
